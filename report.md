# Архітектурний звіт

## 🔴 Проблема №1: Відсутня типізація та перевірка даних

**Файл:** main.py

**Суть проблеми:**
- Відсутня типізація параметрів функцій.
- Відсутній `response_model` для перевірки вихідних даних.
- Відсутні схеми вхідних даних (наприклад, Pydantic).

**Порушений принцип:**
- "Fail Fast" — відсутність ранньої перевірки даних.
- "Видимість" — немає чіткої структури API.

**Чому інструменти не спрацюють:**
- **Semgrep** не може визначити SQL injection без типів.
- **DAST** не зможе згенерувати тести через відсутність OpenAPI.

**Посилання на конспект:**
- Документ 14, розділ "OpenAPI + типізовані моделі у FastAPI".

**Рекомендації:**
- Використовувати Pydantic для типізації та перевірки даних.
- Додати `response_model` для перевірки вихідних даних.
- Додати схеми для вхідних даних.

**Код:**
```python
# ❌ Поточний код:
@app.get("/user")
def get_user(id):
    return {"id": id, "name": "Alice"}

# ✅ Виправлений код:
from pydantic import BaseModel

class UserResponse(BaseModel):
    id: int
    name: str

@app.get("/user", response_model=UserResponse)
def get_user(id: int):
    return {"id": id, "name": "Alice"}
```

## 🔴 Проблема №2: Відсутнє безпечне зберігання секретів

**Файл:** deployment.yaml

**Суть проблеми:**
- Відсутні механізми для безпечного зберігання секретів (наприклад, Vault або CSI).

**Порушений принцип:**
- "Принцип мінімальних привілеїв" — секрети доступні у відкритому вигляді.

**Чому інструменти не спрацюють:**
- **Gitleaks** знайде секрети лише після їх коміту.
- **OPA** не зможе заблокувати hardcoded secrets без політики.

**Посилання на конспект:**
- Документ 14, кейс "Vault CSI для зберігання секретів".

**Рекомендації:**
- Використовувати HashiCorp Vault або Kubernetes Secrets для зберігання секретів.
- Інтегрувати CSI драйвер для автоматичного монтування секретів.

**Код:**
```yaml
# ❌ Поточний код:
env:
  - name: API_KEY
    value: "sk_live_ABC123"

# ✅ Виправлений код:
volumeMounts:
  - name: secrets-store
    mountPath: "/mnt/secrets-store"
    readOnly: true
volumes:
  - name: secrets-store
    csi:
      driver: secrets-store.csi.k8s.io
      volumeAttributes:
        secretProviderClass: "vault-secrets"
```

## 🔴 Проблема №3: Відсутність SAST у CI/CD

**Файл:** ci.yml

**Суть проблеми:**
- Відсутні інструменти для перевірки безпеки, такі як Semgrep або Bandit.

**Порушений принцип:**
- "Shift Left" — перевірки безпеки повинні виконуватись на ранніх етапах.

**Чому інструменти не спрацюють:**
- Без SAST у CI/CD вразливості потрапляють у production.

**Посилання на конспект:**
- Документ 13, розділ "SAST у CI/CD".

**Рекомендації:**
- Додати Semgrep для статичного аналізу коду.
- Інтегрувати Bandit для перевірки Python-коду.

**Код:**
```yaml
# ✅ Виправлений код:
steps:
  - name: Run Semgrep
    run: semgrep --config=auto .
  - name: Run Bandit
    run: bandit -r .
```

## 🔴 Проблема №5: Відкритий Security Group у Terraform

**Файл:** main.tf

**Суть проблеми:**
- Вхідний трафік дозволений з будь-якої IP-адреси (`0.0.0.0/0`).

**Порушений принцип:**
- "Принцип мінімальних привілеїв" — доступ має бути обмежений лише необхідними адресами.

**Чому інструменти не спрацюють:**
- **OPA** не зможе заблокувати відкритий доступ без політики.

**Посилання на конспект:**
- Документ 15, розділ "Обмеження доступу в Terraform".

**Рекомендації:**
- Обмежити доступ до певних CIDR блоків.

**Код:**
```hcl
# ✅ Виправлений код:
ingress {
  from_port   = 443
  to_port     = 443
  protocol    = "tcp"
  cidr_blocks = ["192.168.1.0/24"]
}
```
